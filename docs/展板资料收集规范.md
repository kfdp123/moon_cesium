# 展板与科普资料收集目录

本规范中的“展板”包括独立科普主题，以及着陆点、月海、环形山等点位的介绍内容。资料收集入口为工程根目录的 `资料收集/`，原始资料不自动提交到 GitHub。

## 一、目录

```text
资料收集/
├─ 00_模板/
│  └─ 单块展板/                  ← 复制整个文件夹，一块展板一份
│     ├─ 展板信息.md
│     ├─ 正文.md
│     ├─ 素材说明.md
│     ├─ 图片/
│     ├─ 模型/
│     ├─ 文献/
│     └─ 视频/                   ← 可选，当前系统尚无专门视频播放器
├─ 01_科普展板/
│  ├─ 01_认识月球/
│  ├─ 02_月球形成与演化/
│  ├─ 03_内部结构/
│  ├─ 04_月海与环形山/
│  ├─ 05_探月任务与着陆点/
│  └─ 06_月面环境与未来基地/
├─ 02_年代场景/
│  ├─ 01_约44至45亿年前/
│  ├─ 02_约43亿年前/
│  ├─ 03_约38亿年前/
│  └─ 04_现今月球/
├─ 03_地图数据/
│  ├─ 01_DEM高程/
│  ├─ 02_月表影像/
│  ├─ 03_地质与专题图/
│  └─ 04_矢量数据/
└─ 99_待整理/                    ← 暂时不知道用途的资料先放这里
```

分类文件夹下再放具体展板，例如 `01_科普展板/05_探月任务与着陆点/apollo-11_阿波罗11号着陆点/`。直接复制模板并重命名即可；每块展板建议用一个稳定编号，后续更新不要更换编号。年代场景下也可放多块展板。

## 二、一块展板怎么收集

最少填写：编号、标题、内容类型、简短介绍、来源链接。已有长介绍放入 `正文.md`，可以直接粘贴文字；也可以先存 Word 原件，由接入时整理。没有的项目写“待补充”，不必为填满模板编造内容。

点位类还需要经纬度及坐标来源；不知道时留空，不能用 0、0 占位。已在系统目录中的点位，只需提供名称或原点位 ID，接入时匹配原坐标。独立主题展板不需要坐标。

每张图片、模型、文献等在 `素材说明.md` 记录文件名、显示标题、原始网页、作者/机构、使用许可与必要图注。信息暂时不确定可写“待核实”。同一素材可供多块展板引用，注明现有文件位置即可，不必反复下载。

| 材料 | 优先形式 | 收集约定 |
|---|---|---|
| 文字 | 独立可编辑文字 | 不要只存排好版的展板截图；如有截图，也保留原文 |
| 图片 | JPG、PNG、WebP 原图 | 用可辨认名称，如 `01_着陆舱全景.jpg`；记录图注和来源，不去除水印 |
| 模型 | GLB 优先；glTF 配套文件完整 | OBJ/FBX 等原件也可保留，接入时转换；注明尺寸单位、实测或示意 |
| 文献 | PDF 或 DOI/原文链接 | 记录题目、作者、年份；不能分发全文时保留文献信息和链接 |
| 外部链接 | 原始网页地址 | 保存网址文字，不要只保存浏览器快捷方式 |
| 视频 | MP4 或原视频链接 | 可选，当前需后续补充视频展示支持 |

## 三、地图数据单独收集

一个数据集一个目录，保留下载的全部配套文件，并复制填写 `00_模板/地图数据说明.md`。记录来源、数据类型、坐标系、经纬度方向、分辨率、数值单位、无效值、适用年代；未知项直接标“待核实”。

在线服务优先保存产品网页、服务地址和示例；DEM 保留原始高程文件而非地形截图；Shapefile 的 `.shp/.shx/.dbf/.prj` 等配套文件应放在一起。PDF 地图或图片可以作为展板插图，但不能直接等同于有坐标的地图图层。

## 四、与当前系统的关系

当前点位详情已经支持文字、图片、一个 GLB/glTF 模型、文献链接和相关链接。现有“点位管理”导入入口接收 GeoJSON，不会自动扫描上述文件夹。

按本目录收集后，可以批量进行“读取资料 → 检查来源和坐标 → 发布可用素材 → 转为系统数据 → 导入并验看”。收集阶段不用修改前端代码，也不用自己制作 GeoJSON。匹配现有点位时保持原 ID，避免重复点。

独立主题展板没有坐标，不能硬塞成地图点；其浏览入口需要补充开发。视频、PDF 内嵌阅读、非 GLB 模型转换，以及不同投影地图/原始 DEM 的处理，也可能需要适配。目录规范使资料容易接入，不代表任意格式文件放进去便立即显示。

建议先整理 2–3 块有代表性的展板（一个着陆点、一个环形山或月海、一个内部结构主题），完成一次接入确认，再批量收集。
