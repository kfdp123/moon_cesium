# 月球 Web 系统：开源调研与复用评估

调研日期：2026-09-14。用途：为本项目的实施方案提供选型依据。

本次检查了项目主页、README、可访问的许可证、依赖清单及部分官方示例代码。没有安装运行这些完整系统，没有做漏洞扫描、全仓代码审计或性能实测。下文“可参考”不等于已经验证能直接集成。网页描述和默认分支可能变化；实际引入时必须锁定版本或提交。

## 1. 结论

找到相关系统与组件，但本次没有找到可以直接覆盖“月表数据 + 内部圈层剖切 + 月球早期演化 + 算法成果接入”的完整开源成品。

- 最接近完整行星信息系统：**NASA-AMMOS/MMGIS**。优先借鉴数据目录、图层配置、查询与剖面工作流；保留为科研功能扩大后的整套底座候选。
- 最接近月球科普主题：**Lunar Trek**。借鉴月球热点与讲解的组织方式；其 React/Three.js 页面不直接搬入 Vue 工程。
- 最适合当前主渲染基础：**CesiumJS**。现有 HTML 已使用，适合继续验证月表与专题图层。用户已确认第一版在线使用，离线作为后续增强。
- 内部剖切技术参考：**Three.js 官方 clipping/stencil 示例**。先借鉴几何和封口思路，不默认增加第二个渲染引擎。
- 展示素材优先：**NASA SVS 的月球模型与 CGI Moon Kit**。显示素材和科学数值数据分别登记。

判断依据是本项目以科普展示为主、现有代码只有单页、需要 Web 访问和后续成果接入。直接修改大型 GIS 系统仍需要新做内部演化、科普界面与内容编排，未必比使用成熟组件组装更省工作。

## 3. 重点项目的具体参考位置

### 3.1 MMGIS：借鉴“数据有配置、图层有来源、查询有原值”

官网和仓库均说明了行星地图、可配置图层和剖面功能。其 [Measure 文档](https://nasa-ammos.github.io/MMGIS/tools/measure)介绍了按配置选择 DEM、绘制剖面以及导出采样值的流程。

建议对本项目做三项转化：

1. 图层目录统一保存资源、单位、图例、适用年代和查询能力，而不是在按钮里直接写图片路径。
2. 剖面曲线关联真实采样数据及三维位置；图表和月球视图共用选择状态。
3. 数据管理页面负责配置，展示页面只读取已发布的配置版本。

进一步阅读入口：

- [官方文档](https://nasa-ammos.github.io/MMGIS/)
- [投影配置](https://nasa-ammos.github.io/MMGIS/configure/tabs/projection)
- [依赖清单](https://github.com/NASA-AMMOS/MMGIS/blob/development/package.json)
- [LICENSE](https://github.com/NASA-AMMOS/MMGIS/blob/development/LICENSE)

依赖清单可见 React、Express、Cesium、Lithosphere 等组件；直接整体采用意味着要接受并维护它的既有技术体系。本轮不把 MMGIS 接到 Vue 中再另建同一套后台。若未来需求明显转向复杂科研 GIS，再安排独立试装，比较配置覆盖度、改造量、部署资源与维护成本。

### 3.2 Lunar Trek：借鉴“围绕问题和地点讲月球”

其 [README](https://github.com/yousefkotp/Lunar-Trek)描述月震与阿波罗相关科普功能；[package.json](https://github.com/yousefkotp/Lunar-Trek/blob/main/package.json)确认 Web 使用 React、React Three Fiber、Three.js 和 Recharts；[LICENSE](https://github.com/yousefkotp/Lunar-Trek/blob/main/LICENSE)为 MIT。

本项目可以采用“选择一个地点或事件 → 镜头定位 → 显示短讲解 → 展开数据”的交互。具体文字、数据和组件重写为本项目结构。它与 NASA 官方 Moon Trek 不是同一个系统；参与 NASA Space Apps 也不表示其全部科学内容已由 NASA 审定。

### 3.3 CesiumJS：继续使用，但不沿用旧页的技术缺陷

[官方仓库](https://github.com/CesiumGS/cesium)提供三维与空间数据基础；[离线指南](https://github.com/CesiumGS/cesium/blob/main/Documentation/OfflineGuide/README.md)给出本地部署方向。

实施时保留月球坐标、图层叠加和相机控制基础能力；重做结构模型、选择判定和配置服务。版本由初始验证锁定，不因现有 HTML 用了 1.115 就永久绑定，也不直接采用浮动最新版。

### 3.4 Three.js 示例：封口是一项独立实现工作

已阅读 [clipping stencil 示例代码](https://github.com/mrdoob/three.js/blob/dev/examples/webgl_clipping_stencil.html)。它演示了裁剪与模板缓冲配合形成切面，说明“裁掉外壳”与“形成可观看的封口”是不同工作。

本项目球形分层先做参数化实体截面，规则明确、便于拾取和测试。任意非球形模型的切面必须另行处理，不能把球体封口算法套到所有模型上。若 Cesium 实测不能满足内部表现，再小范围验证 Three.js 内部模式；不直接把示例当作已完成的多层月球剖切。

## 4. 展示素材与科学数据来源

| 入口 | 可以解决的问题 | 使用要求 |
|---|---|---|
| [NASA SVS Moon 3D Models](https://svs.gsfc.nasa.gov/14959/) | 月球展示模型资源候选 | 记录具体文件、来源、署名、几何坐标与单位，不能只凭文件名认定本地文件同源 |
| [NASA SVS CGI Moon Kit](https://svs.gsfc.nasa.gov/4720/) | 月球颜色、位移纹理；包含 16 像素/度的 DEM 资源 | 颜色贴图经过展示加工；数值查询读取合适的原始 DEM，记录编码、比例和参考半径 |
| [NASA Solar System Treks](https://trek.nasa.gov/) | 公开图层发现与 WMTS 服务方向 | 第一版可使用适合的在线资源，记录服务依赖；离线复制能力另行核实 |
| 工作区上级目录的 DEM/DOM/tiles | 已有本地数据候选，可能减少下载和加工 | 后续读取元数据核实投影、瓦片规则、值域与许可证；本轮只做过目录级盘点 |

CGI Moon Kit 的 16 像素/度在角分辨率上对应 0.0625°；这只是候选数据与合同角间隔的匹配，不代表合同全部数据精度或验收条件已经满足。其页面明确区分了展示用颜色图与科学源数据。

## 5. 四条路线的工程判断

| 路线 | 优势 | 额外工作 | 判断 |
|---|---|---|---|
| 整套 MMGIS 二次开发 | 地图和数据管理已有大量能力 | 科普界面、内部模型、演化模块仍需开发，且需接手既有栈 | 科研管理需求扩大时复评 |
| Vue + CesiumJS + 轻量后端 | 延续现有经验，界面和业务可按目标控制 | 需自建有限的数据目录、模型与演示模块 | 当前推荐 |
| Vue + CesiumJS 月表 + Three.js 内部模式 | 内部效果可使用专门渲染实现 | 两个适配器、资源生命周期和状态转换 | Cesium 内部原型不达标时的候选 |
| Vue + UE5 + Pixel Streaming | 可开展较复杂的视觉效果制作 | UE 工程、GPU 渲染部署、串流与独立会话管理 | 单独效果试验，不作为首版前置条件 |

这里不预设“Web 一定足够”或“UE5 一定更好”。先用同一组场景在目标电脑验证模型清晰度、切面、拾取和播放，再决定是否调整。

## 6. 实际复用的执行规则

1. 只采用本期确实需要的组件，不因一个系统能力多就全部引入。
2. 直接复制代码前记录仓库 URL、版本/提交、源文件、许可证和修改范围；连同署名文件交付。
3. 代码许可证、数据许可、美术资产许可分别检查；第三方标识不作为项目自身标识。
4. 优先使用官方稳定 API，不沿用旧仓库的私有接口、过时构建脚本和硬编码服务地址。
5. 先验证一个小样例的运行与数据准确性，再接入正式流程。
6. 本次没有下载整套第三方源码或修改现有 HTML；后续采用范围应追加到第三方清单中。
