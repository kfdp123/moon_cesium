# V0.2 参数模型、科普数据与漫游扩展

日期：2026-09-14。此次按用户新要求调整产品结构：月表和内部不再分为两个入口，统一由参数、剖切、图层和年代控制。此说明更新原实施方案中涉及这部分交互的约定。

## 本次实现

| 模块 | 功能 | 保存与边界 |
|---|---|---|
| 参数模型 | 总半径、圈层厚度、颜色、名称、增删、显隐、三种剖切 | 最多 8 层，同心球壳；可按年代保存到本浏览器 |
| 年代场景 | 约 44–45、43、38 亿年前及现今 | 模拟圈层参数；早期表面、热状态与科学模型尚待接入 |
| 地图管理 | 6 个内置资源，显隐、透明度、顺序、删除、自定义在线影像 | 可保存图层配置；自定义瓦片只接受月球等经纬度 2×1 起始矩阵 |
| 科普点位 | 388 个点，搜索、分类、增删改、显隐、GeoJSON 导入导出 | 本浏览器持久化，尚非多用户服务端管理 |
| 点位详情 | 三维点选、文字、照片、独立可旋转模型、文献、相关链接 | 缺失资源明确显示未提供；阿波罗 11 号具备完整素材链 |
| 漫游 | 第一视角、自动环游基地、第三人称人物 | 原创示意平台/基地/人物；WASD、方向键、Shift；基础舱体阻挡 |
| 太阳系 | 完成开源参考与架构评估 | 用户标为可选，本次未实现 |

修改圈层厚度时，所有相邻边界重新连续计算，总半径随之变化；修改总半径时全部圈层同比缩放。保存当前年代参数后切换或刷新可恢复，恢复默认可移除该年代保存值。显示参数、详情及几何使用同一份模型。

## 数据来源与实际接入

### 地图与高程

NASA Trek 的 [官方 WMTS API](https://trek.nasa.gov/tiles/apidoc/trekAPI.html?body=moon) 发布月球瓦片。此次读取服务配置与 Capabilities，核验了等经纬度、2×1 起始瓦片矩阵、256 像素瓦片、层级和跨域响应；并在浏览器里实际请求成功。

| 产品 | 类型 | 服务产品标识 / 层级 |
|---|---|---|
| NASA LRO 展示影像 | 本地 RGB 图片 | CGI Moon Kit 2K |
| LROC WAC 全球影像 | 在线 WMTS REST 瓦片 | LRO_WAC_Mosaic_Global_303ppd_v02 / 0–8 |
| LOLA 彩色晕渲 | 高程派生图片 | LRO_LOLA_ClrShade_Global_256ppd_v06 / 0–6 |
| LOLA 阴影地形图 | 高程派生图片 | LRO_LOLA_Shade_Global_256ppd_v06 / 0–6 |
| 月球统一地质图 | 地质单元着色图片 | Unified_Geologic_Map_of_the_Moon_RASTER / 0–5 |
| LOLA 三维高程 | 本地实际高程网格 | 1440×720、0.25°，由 CustomHeightmapTerrainProvider 提供三维瓦片 |

高程源为 [NASA CGI Moon Kit](https://svs.gsfc.nasa.gov/4720/) 的 `ldem_4_uint.tif`。源文件单位为半米，相对 1727400 m；转换为相对 1737400 m 的高程使用 `value × 0.5 − 10000`，再取整为有符号米，最大量化误差 0.5 m。保存为 little-endian Int16；行从北向南，列从 -180° 向东。经度边界循环、纬度边界夹取，采样使用双线性插值。

0.25° 全球高程适合概览，不满足合同 0.0625° 的最终数据分辨率，也不代表基地尺度的真实地形。半径被用户改变时，高程幅度仍保留米制值，显示属于参数实验。早期场景叠加的影像、地形和地质图仍然是现今资料，不能当作早期月表重建。

### 点位

从 [USGS / IAU GIS 下载页](https://planetarynames.wr.usgs.gov/GIS_Downloads) 下载 Moon KML，使用其中心点、名称、地貌类别、目录直径、命名来源及记录链接。筛选月海、月洋和直径不小于 80 km 的主环形山，并保留精选地貌；名称原文没有经过机器翻译。目录有 380 个地貌中心点。

另外 8 个点位为阿波罗 11/12/14/15/16/17 着陆点、嫦娥三号和玉兔记录位置，坐标来自 [LROC 2016 人工目标坐标表](https://www.lroc.asu.edu/data/support/downloads/2016_LROC_Coordinates_of_Human_Features.pdf)。所有经度转换到 [-180, 180]，东经为正。巡视器位置不是实时位置。点表示目标/地貌中心，不代表范围边界。

阿波罗 11 号详情照片来自 [NASA/JSC 历史照片](https://science.nasa.gov/resource/view-apollo-11-lunar-module-as-it-rested-on-lunar-surface/)，模型来自 [NASA/Michael D. Carbajal](https://science.nasa.gov/3d-resources/apollo-lunar-module/)。模型是登月舱表现模型，不是着陆区实测扫描。

转换脚本：`moon-web/scripts/prepare_public_data.py`。执行前需将下载资料放入脚本注明的 `tmp/` 路径并安装 Pillow；前端日常构建不依赖 Python。分发用 GeoJSON 和高程二进制已入工程。

## 漫游与开源判断

| 参考 | 可借鉴内容 | 本次决定 |

本版未复制这些仓库的源码或角色资产。基地、平台与人物为本项目原创简化几何，位于示意坐标 20°W、10°N。基地漫游使用局部平台；采样高程用于平台定位，不声称实现真实月面行走物理。人物尚无骨骼行走动画、跳跃或装备系统。

## 太阳系可选扩展建议

可以加入日地月和太阳系，但应做独立场景入口，复用点位详情与资源管理。第一步为日地月、时间控制、真实比例与教学夸张比例切换；第二步再加其余行星和镜头导航。科普轨道可以明确标注为简化轨道；若需要日期精确位置，应接入经过核对的星历并处理惯性/固连参考系。

不要让一个镜头同时承担米级基地、百万米级月球和天文单位级太阳系。建议切换场景时销毁上一套渲染资源，以局部原点和各自相机尺度控制精度与内存。Three.js 适合独立太阳系页面；当前月球保留 Cesium。是否引入第二个引擎应在太阳系原型效果评审后决定。
